VISUAL REFERENCE — TARGET UI / UX

The attached Jenga Video Studio concept image is the primary visual reference for how the finished application should feel.

Do NOT attempt to reproduce the image pixel-for-pixel, and do not sacrifice existing functionality merely to match the mockup. Instead, use it as the design target for layout, hierarchy, density, navigation, component styling and overall product quality.

The important characteristics of the reference are as follows.

OVERALL APPEARANCE

The application should look like polished commercial Windows creative software rather than a developer utility, configuration form or website placed inside a desktop window.

The visual identity consists of:

- very dark navy main background
- slightly lighter navy panels/cards
- turquoise/aqua as the primary accent
- white high-priority text
- muted blue-grey secondary text
- thin/subtle borders
- restrained shadows
- modest corner rounding
- generous but efficient spacing
- consistent typography
- clear icons
- strong contrast between primary and secondary controls

The interface should feel sophisticated and technical without looking complicated.

Avoid giant empty areas and avoid filling the application with identical rectangular buttons.

--------------------------------------------------
1. PERMANENT APPLICATION HEADER
--------------------------------------------------

Across the top is a relatively compact application header.

Left:

JENGA VIDEO STUDIO
An idea. A researched story. Your next video.

The Jenga branding should be prominent but should not consume excessive vertical space.

Right:

- Help
- Settings
- current user/account information where applicable
- normal Windows window controls

The header establishes the application identity without dominating the working area.

5. PROJECT WORKFLOW
--------------------------------------------------

Once a project is opened, display its lifecycle clearly.

1  Create
   Your idea

2  Production

3  Review

This is superior to treating every stage as an unrelated application page.

The user should understand that these screens are stages in ONE VIDEO PROJECT.

7. PIPELINE VISUALISATION
--------------------------------------------------

✓ Evidence
✓ Script

○ Visuals

The normal user sees a concise activity feed such as:

19:57:43  Scene 3 script completed
19:57:34  Generating image for scene 3...
19:56:21  Scene 2 completed

--------------------------------------------------
15. INFORMATION DENSITY
--------------------------------------------------

Notice that the reference image contains a LOT of information without appearing chaotic.

Achieve this through hierarchy rather than simply removing functionality.

Important information is large.

Secondary information is smaller.

Technical information is subdued.

Primary actions are brightly accented.

Completed states use small status indicators.

Panels are clearly grouped.

Whitespace separates concepts rather than producing enormous unused regions.

The goal is efficient use of a desktop monitor.

--------------------------------------------------
16. BUTTON HIERARCHY
--------------------------------------------------

Not every action should look equally important.

PRIMARY ACTION:

Bright turquoise/accent.

Examples:

Create New Video
Create Video
Render Final Video

SECONDARY ACTION:

Dark blue with subtle border.

Examples:

Open
Save Changes
Regenerate Visual
Manage Components

TERTIARY ACTION:

Text/icon controls.

Examples:

Advanced
View Log
More
Help

DESTRUCTIVE ACTION:

Clearly differentiated.

Examples:

Cancel
Delete Project

Do not use turquoise for every clickable element.

--------------------------------------------------
17. COMMERCIAL PRODUCT FEEL
--------------------------------------------------

The final interface should make somebody unfamiliar with the implementation think:

"This is an AI video creation application."

It should NOT make them think:

"This is a GUI someone built around some command-line AI tools."

Ollama, FFmpeg, Piper, ComfyUI and other underlying technologies are implementation details.

They should remain accessible to advanced users but should not define the consumer experience.

--------------------------------------------------
18. IMPORTANT: THE IMAGE IS A DESIGN REFERENCE,
NOT A NEW SPECIFICATION
--------------------------------------------------

The attached image contains illustrative content such as example projects, thumbnails, statuses and progress.

Do NOT hard-code those examples.

Do NOT create fake projects.

Do NOT create fake progress.

Do NOT replace working backend functionality merely because something in the concept image is different.

Instead map the EXISTING Jenga Video Studio functionality onto this visual structure.

Do not implement deceptive placeholder behaviour.
